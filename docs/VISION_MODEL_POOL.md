# 独立识图模型池

`api.visionModel.model` 保留原有单模型配置；`models` 可以加入同一提供商、
同一 API 地址和凭据下的额外识图模型。模型 ID 去空白、去重后，所有独立
识图请求按轮询顺序分配，包括聊天图片描述、表情收藏判断及其请求级重试。
优先选择没有进行中/排队任务、不在限频间隔或 429 冷却期内的模型；当前
轮到的模型忙时跳到下一条可用通道。全部通道都忙时，选择冷却最短、排队
最少的通道等待。收到 429 时可立即尝试池中其他模型，原模型保留冷却时间。
状态查询和视觉能力检查不占用轮询次数，主聊天模型不参与这个池。

`strategy: "priority"` 改为优先使用 `model`，`models` 中的其他模型只作为
备用。主模型繁忙时先在队列中等待；超过 `queueTimeoutMs`（默认 10000
毫秒）、请求超时或出现可重试故障后，当前任务改用备用模型，每条通道至多
尝试一次。已知 429 冷却中的模型直接跳过。后续新任务仍优先主模型，不会
因上一个任务用了备用而交替使用两者。

例如 DS4 优先、HY3 备用：`model: "deepseek-v4.1-flash"`、`models: ["hy3"]`、
`strategy: "priority"`、`queueTimeoutMs: 10000`、`timeoutMs: 30000`、
`fallbackTimeoutMs: 60000`。排队超时只取消队列中的任务，不中断原有进行中的
请求。调用方的取消、运行总超时和非活跃时间限制始终优先于备用切换。

主聊天通过 `api.model` 和 `api.fallback` 单独设置；已配置备用时，主模型
首次请求超时或 429 后直接转备用，避免同一模型的多轮等待耗尽运行总预算。

```json
{
  "api": {
    "visionModel": {
      "enabled": true,
      "provider": "your-provider-id",
      "model": "vision-model-a",
      "models": ["vision-model-a", "vision-model-b"],
      "balanceFrom": "2026-10-13T00:00:00+08:00",
      "thinking": "off",
      "requestIntervalMs": 2000,
      "timeoutMs": 90000
    }
  }
}
```

分配按请求次数；所有模型均空闲时顺次轮询，忙碌或冷却中的模型会跳过，
不保证调用数严格相等。token 数也会随图片和返回内容变化。轮询位置在
进程内保存，重启后从首个模型开始，
不会为历史用量补偿分配。没有 `models` 或只有一个有效模型时保持单模型行为。

可选的 `balanceFrom` 是带时区的 ISO 日期：到该时间之前只使用 `model`，
到点后自动启用全部模型，无需定时重启。空值立即启用模型池；无效日期保守
保持单模型。`thinking: "off"` 单独关闭独立识图模型的思考，不受主聊天模型
或判断任务的通用思考档位影响；不填写时沿用已有的提供商思考设置。

同一地址、凭据和模型的独立识图请求串行执行，聊天图片描述和表情判断共享
队列。`requestIntervalMs` 指请求启动的最小间隔，默认 2000 毫秒（0 只保留
串行，不额外限频）。其他模型可同时运行，主聊天不加入识图队列。

HTTP 429 的 `Retry-After`（秒数或 HTTP 日期）和 JSON `retry_after` 都会参与
共享冷却；缺少有效时间时等待 60 秒。冷却期间不发送该模型的新请求，取消
或超时的排队任务不会发出请求，也不会卡住后面的任务。冷却时间超过请求
预算时直接返回 429，避免把长时间额度限制变成反复重试的超时。表情自动
收藏不会在已有的图片下载重试、模型重试之外再重复整段判断。

`GET /api/vision/results` 的 `visionModel.models` 与 `distribution` 返回模型池
和分配方式，`activeModels` 返回当前实际启用的模型，`balanceFrom` 返回预约时间。
`data/usage-all.jsonl` 的 `requestedModel` 记录实际请求的模型 ID；
`model` 继续记录供应商返回的模型名，避免接入点被同一模型别名遮住。

恢复单模型：将 `api.visionModel.models` 设为 `[]`，保留原来的 `model`。
运行中的实例应通过配置 API 保存，或编辑配置后重启服务使其生效。
